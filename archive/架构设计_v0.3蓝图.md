# 架构设计文档（Architecture Design）
## 《迈克尔·杰克逊：人生选择》技术架构重设计方案

> 本文档针对 v0.3 可运行原型（单文件 `迈克尔·杰克逊：人生选择.html`）的局限性，提出一套**数据驱动、可测试、可扩展**的新架构。目标是解决现有问题（财富数值 bug、属性联动缺失、无存档、内容硬编码、无多语言），同时保留“H5 单文件可部署、低门槛”的产品特性。
>
> 本文**不修改现有 HTML**，仅作为目标架构与迁移蓝图。

---

# 一、设计目标与原则

| 原则 | 说明 |
| --- | --- |
| 数据 / 逻辑分离 | 所有剧情、事件、结局、文案以**数据（JSON + i18n）**描述，引擎只读数据，策划可热插拔内容 |
| 数值模型自洽 | 消除“0–100 区间写入 -2600”的尺度冲突（见第九章） |
| 可测试 | 结局判定、数值结算、存档校验等核心逻辑不依赖 DOM，可单元测试 |
| 可扩展 | 新增事件/章节/结局 = 新增数据，无需改引擎代码 |
| 多语言 | 文案与逻辑解耦，运行时按 locale 查表 |
| 可部署 | 构建产物仍可输出为单文件 H5，双击即玩 |
| 存档安全 | 自动存档 + 版本校验 + 多周目槽位 |

# 二、总体架构（分层）

```
┌─────────────────────────────────────────────┐
│            表现层 Presentation                │  UI 组件 / 动画 / 音频
├─────────────────────────────────────────────┤
│            应用层 Application                 │  游戏流程编排 / 路由 / 屏幕切换
├─────────────────────────────────────────────┤
│            领域层 Domain (核心规则)           │  StateManager / EventEngine
│                                             │  OutcomeResolver / RuleEngine
├─────────────────────────────────────────────┤
│            数据层 Data                        │  events / endings / attributes
│                                             │  flags / i18n  (纯 JSON, 可热更)
├─────────────────────────────────────────────┤
│            基础设施 Infra                     │  SaveSystem / Analytics
│                                             │  I18n / Logger / Validator
└─────────────────────────────────────────────┘
```

依赖方向自上而下（上层依赖下层，下层不反向依赖）。领域层不引用任何 DOM API，从而保证可测试性。

# 四、数据层设计

## 4.1 事件数据 Schema（JSON）
用声明式结构替代原 `createEvent(id, year, title, descFn, optsOrAuto)` 的 JS 函数式写法：

```json
{
  "id": "3_2",
  "chapter": 3,
  "year": 1984,
  "type": "choice",                 // choice | auto
  "condition": { "flags": { "isSolo": true } },  // 可选
  "fallback": "4_1",                // condition 不满足时跳转
  "title": "pepsi_title",           // i18n key
  "desc": "pepsi_desc",             // i18n key, 支持 {{var}}
  "options": [
    {
      "id": "A",
      "text": "pepsi_A_text",
      "hint": "pepsi_A_hint",
      "effects": { "attributes": { "wealth": 20, "reputation": 5 },
                   "money": 500 },   // 万美元：广告收入（见 Economy）
      "flags": { "isPepsiBurned": true },
      "next": "3_3"
    }
  ]
}
```

- **动态文本**：原代码用 `function(){return isSolo?...:...}`。改为 `desc` 引用 i18n key，引擎根据当前 flags 选择变体 key（如 `pepsi_desc_solo` / `pepsi_desc_group`），或用 `{{isSolo}}` 插值 + 条件片段。
- **auto 事件**：`"type":"auto", "effects":{...}, "next":"..."`，无 options。

## 4.2 属性定义（attributes.json）
```json
[
  {"key":"health","init":70,"min":0,"max":100,"labelKey":"attr_health"},
  {"key":"reputation","init":50,"min":0,"max":100,"labelKey":"attr_reputation"},
  {"key":"wealth","init":20,"min":0,"max":100,"labelKey":"attr_wealth"},
  {"key":"family","init":60,"min":0,"max":100,"labelKey":"attr_family"},
  {"key":"art","init":30,"min":0,"max":100,"labelKey":"attr_art"},
  {"key":"stress","init":20,"min":0,"max":100,"labelKey":"attr_stress"}
]
```

## 4.3 标志注册表（flags.json）
显式声明所有标志的类型与默认值，替代散落在代码里的 `state.flags = {...}`：
```json
[
  {"key":"isSolo","type":"enum","values":[null,true,false],"default":null},
  {"key":"neverlandType","type":"enum","values":["public","private","none"],"default":"public"},
  {"key":"painkillerDependent","type":"bool","default":false},
  ...
]
```
`Validator` 在加载时校验事件引用的 flag 均已注册，避免拼写错误。

# 五、领域层（核心规则）

## 5.1 StateManager
- 持有 `attributes`（6 项）、`flags`、当前 `eventId`、隐藏 `economy`（见 5.5）。
- 提供 `applyEffects(effects)`、`setFlags(flags)`、`goTo(id)`。
- 每次变更生成**不可变快照**（便于撤销/回放/测试）。
- `clamp` 仅作用于 0–100 展示属性；货币走 Economy 子系统，不受此 clamp 影响。

## 5.2 EventEngine
职责：
1. 按 `eventId` 取事件数据。
2. 解析 `condition`：不满足则走 `fallback`。
3. 渲染前用 I18n 把 key 解析为当前语言文本，做变量插值。
4. 处理选项点击 → 调用 `StateManager.applyEffects` / `setFlags` → `goTo(next)`。
5. 支持“条件选项”：某选项带 `visibleIf`，不满足则不渲染（替代原代码 `.filter(opt=>opt.condition())`）。

## 5.3 RuleEngine（修复属性联动缺失）
把“压力影响健康”等设计为**可配置规则表**，在章节推进结算时执行：
```json
[
  {"when":"chapter_end","rule":"health -= floor(stress/20)"},
  {"when":"chapter_end","rule":"if stress<25 then art += 5"},
  {"when":"event:3_4","rule":"if painkillerDependent then stress += 10"}
]
```
引擎解释执行（或编译为函数）。这样设计意图真正落地，且无需改代码即可调参。

## 5.4 OutcomeResolver（结局判定，可测）
将 v0.3 的 `getEndingEventId` 改写为**规则表 + 优先级**，与 DOM 解耦：
```json
[
  {"id":"END_PLAIN",        "priority":100, "when":{"eventId":"END_PLAIN"}},
  {"id":"END_FAMILY",       "priority":90,  "when":{"flags":{"isSolo":false}}},
  {"id":"END_PERFECT",      "priority":80,  "when":{"not":{"flags":{"isPepsiBurned":true}},
                                                   "attrGte":{"health":70},
                                                   "any":[{"flags":{"thisItHeld":false}},
                                                          {"flags":{"thisItScale":"reduced"}}]}},
  {"id":"END_ART_PEAK",     "priority":75,  "when":{"flags":{"isPepsiBurned":true,"painkillerDependent":false,"thisItHeld":true,"thisItScale":"full"}}},
  {"id":"END_TRAGIC",       "priority":70,  "when":{"flags":{"isPepsiBurned":true,"painkillerDependent":true,"thisItHeld":true,"thisItScale":"full"}}},
  {"id":"END_FINANCIAL",    "priority":60,  "when":{"economy":{"debt":true}}},        // 改用 economy，见 5.5
  {"id":"END_CONTROVERSIAL","priority":55,  "when":{"attrLt":{"reputation":30},"flags":{"settlement1993":true}}},
  {"id":"END_SURVIVE_DEBT", "priority":50,  "when":{"flags":{"thisItHeld":false},"economy":{"debt":true}}},
  {"id":"END_PERFECT",      "priority":40,  "when":{"attrGt":{"health":60,"reputation":50}}},
  {"id":"END_TRAGIC",       "priority":0,   "default":true}
]
```
- `OutcomeResolver.resolve(state)` 返回首个命中最高优先级的结局 id。
- 纯函数、无副作用 → Vitest 直接覆盖 8 结局。

## 5.5 Economy（修复财富数值 bug —— 核心）
**问题**：当前实现财富是 0–100 属性，却写入 `wealth-2600` 等大值，`clamp` 压到 0，使财务/争议/生存负债结局不可达。

**方案：双轨数值**
1. **展示属性 `wealth`（0–100）**：仅做小幅 ±（±40 上限），用于 UI 与粗略阈值。
2. **隐藏经济变量 `economy`**：
   - `netWorth`（单位：万美元，如初始 50 万，Thriller 后 +3000 万）。
   - `debt`（bool）：当 `netWorth < 0` 自动置 true。
   - 事件用 `effects.money`（万美元 delta）记录真实收支，如和解 -2600 万、Invincible 制作 -3000 万。
3. **财务类结局判定基于 `economy`**：`END_FINANCIAL` 当 `debt===true`；`END_SURVIVE_DEBT` 当 `thisItHeld===false && debt===true`；`END_CONTROVERSIAL` 用 `reputation` 阈值（已合理）。
4. 展示 `wealth` 可由 `netWorth` 经映射函数（如分档或对数）同步，保证 UI 与剧情一致。

> 这样“巨额支出”既在叙事上成立（netWorth 真实变化、触发债务），又不破坏 0–100 属性模型。

# 六、基础设施层

## 6.1 SaveSystem
- **存储**：`localStorage['mjlc_save_v1']`，存 `state` 快照 + `schemaVersion`。
- **自动存档**：每个事件结算后写入（防抖）。
- **版本校验**：`schemaVersion` 不匹配则提示“存档不兼容，重新开始”。
- **多周目槽位**：`slot_0..slot_2`，标题页可选。
- **导入/导出**：JSON 文件，便于分享与调试。

## 6.2 I18n
- 文案全量抽离到 `i18n/zh-CN.json`、`en.json`。
- API：`t(key, vars)`，支持 `{{var}}` 插值。
- 动态文本变体：事件 `desc` 可为对象 `{"solo":"...","group":"..."}`，引擎按 flags 选键。

## 6.3 Analytics（规划 KPI）
- 事件：`game_start`、`event_choose(eventId,optionId)`、`ending_reached(endingId)`、`replay`。
- 默认仅本地 console / 可选上报，尊重隐私。

## 6.4 Validator
- 启动时校验 `events/flags/endings` 引用一致性（flag 已注册、next 目标存在、i18n key 存在）。
- 开发期报错，避免“事件不存在”类运行时崩溃。

# 七、表现层（UI）

- **组件化**：`AttributeBar`、`EventCard`、`OptionButton`、`EndingScreen` 各自负责渲染与交互，仅通过回调把“选择”上报给应用层（不直接改状态）。
- **状态驱动渲染**：应用层拿到新 `state` 后统一 `render(state)`，单向数据流，避免原代码散落的 `innerHTML` 拼接。
- **动画**：属性变化用 CSS transition（保留现有金/黄/红配色）。
- **音频**：可选 BGM + 音效，独立 `AudioManager`，不阻塞交互。
- **可选框架**：若团队熟悉，可用 Preact 或 Vue（体积可控）；若坚持零依赖，可用原生 Web Components。两者都通过 Vite 构建为单文件 H5，**部署特性不变**。

| CI（可选） | 跑测试 + 构建 | 保障质量 |

# 九、关键问题 → 架构对策对照

| v0.3 已知问题 | 新架构对策 |
| --- | --- |
| 财富 -2600 被 clamp 致财务/争议/生存结局不可达 | Economy 双轨数值 + `debt` 标志，结局基于 `economy`（5.5 / 5.4） |
| 压力未真正影响健康 | RuleEngine 规则表，章节结算执行（5.3） |
| 无存档，刷新丢进度 | SaveSystem 自动存档 + 多槽 + 版本校验（6.1） |
| 内容硬编码不可扩展 | 数据层 JSON 化，新增事件=加数据（第三/四章） |
| 无多语言 | I18n 抽离 + 动态文本变体（6.2 / 4.1） |
| 判定逻辑与 DOM 耦合难测 | OutcomeResolver 纯函数 + Vitest（5.4） |
| flag 拼写/遗漏易错 | flags.json 注册表 + Validator 校验（4.3 / 6.4） |

# 十、迁移路线图（从单文件到新架构）

**Phase 0 — 提取（不动玩法）**
- 把现有 `events` 对象转成 `events/*.json`（严格按 4.1 schema）。
- 把 `getEndingEventId` 提取为 `OutcomeResolver` + `endings.json` 规则表。
- 结果：内容与逻辑分离，行为与原版一致。

**Phase 1 — 修数值**
- 引入 `Economy`（netWorth/debt），重写大额收支事件用 `money` 字段。
- 结局判定切到基于 `economy`，使 3 个不可达结局可触发。
- 加 `RuleEngine` 实现压力→健康联动。

**Phase 2 — 工程化**
- 接入 Vite + Vitest，写 OutcomeResolver/Economy 单测。
- 接入 SaveSystem（自动存档）。

**Phase 3 — 体验增强**
- I18n 多语言、UI 组件化单向渲染、Validator 数据校验、Analytics。
- 补充中间事件把节点从 ~36 提升到 50–70（数据层加 JSON 即可）。
